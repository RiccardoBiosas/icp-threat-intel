# OPEN QUESTIONS

Questions the loop could not ask a human. Each entry records the question, the default the agent chose, and the task id. Review these between runs; to change a decision, edit SPEC.md section 2, and delete BLOCKED.md if the loop stopped on it.

| Task | Question | Default chosen | Status |
|---|---|---|---|
| T01 | Guardrail 5 says only "a hash and redacted=true are kept". Redact each matching span or drop the whole body? | Replace each matching span with `[REDACTED:<kind>:<sha256-prefix>]`, keep the rest of the body, set `redacted=true`, keep `sha256` of the original bytes and `stored_sha256` of the stored bytes. Dropping the whole body would destroy H1 evidence whenever a C2 body also contains a token-like string. | open |
| T01 | `raw_snapshots` must be idempotent on identical content. How are repeat observations of an unchanged body recorded? | Unique on `(source_id, url, sha256)`; a repeat returns the existing row and `fetched_at` stays the first fetch. Liveness over time comes from `canister_snapshots` and `events`, which every run writes. No extra table. | open |
| T01 | The census must diff against the previous run, but SPEC's table list has no runs table. | No new table: `canister_snapshots.census_run_id` (UUID) plus one `census.run_completed` event per run with counts, `ceiling_hit` and complete/incomplete subnets. Removals are reported only for subnets complete in both runs. | open |
| T01 | pgvector is in the stack but no table needs a vector column yet. | The initial migration creates the `vector` extension on Postgres only; no vector column until the LLM extension point in `enrichment/` is implemented. | open |
| T01 | For the two-signal rule, does the hand-curated seed file count as its own source type? | No. Each seed IOC carries its original publisher's source type (`threatfox`, `vendor_rss`), so the seed plus the matching ThreatFox collector cannot count as two signals. | open |
| T01 | SPEC says IC canisters can be "disabled" by governance, but IC status values are running/stopping/stopped. | `CanisterStatus` = running, stopping, stopped, unknown. A governance disable shows up as a status change plus a `proposal.references_target` event; there is no separate `disabled` value. | open |
| T01 | The User-Agent must name "a contact address", and the Markdown case report must name the DFINITY security contact. Neither address is given in SPEC. | Contact comes from `ICP_THREAT_INTEL_CONTACT`; live collection (`make record`, scheduler) refuses to start without it, and tests use `test@example.invalid`. The DFINITY security contact is taken from DFINITY's official documentation in T16 and recorded with its source URL. If it cannot be verified, T16 prints a placeholder that tells the operator to fill it in. Nothing is invented. | open |
| T01 | Settings loading: pydantic-settings is not in SPEC's library list. | Use a plain pydantic model populated from `os.environ` with the `ICP_THREAT_INTEL_` prefix; no new dependency. | open |
| T03 | Which hosts go into `ALLOWLIST` before the source notes (T06) exist? | IC hosts only: `icp-api.io`, `ic-api.internetcomputer.org`, `*.icp0.io`, `*.ic0.app`. Registry, abuse.ch, GitHub and vendor hosts are added by their collector tasks once the note verifies the endpoint; nothing is guessed. | open |
| T03 | Should the query-only IC client refuse state-changing method names, given that a query discards state changes anyway? | Yes. Methods whose name words include install, create, update, set, put, transfer, top_up, deposit, notify, stop, start and similar are refused, and so is the management canister `aaaaa-aa`. H1 reads use getters (`get_link`) only. | open |
| T03 | Does the disclosure gate accept a `disclosed_at` in the future or without a timezone? | No. Both are refused, as is a missing value. | open |
| T05 | SPEC names the CanisterWorm write-ups' publishers (Cloud Security Alliance, Aikido, JFrog, Socket) but gives no URLs, and gives no publisher at all for CanisterSprawl. What goes in `source_url` for the two canister IOCs? | An empty string plus the publisher names. Nothing is guessed. Fill the URLs from `docs/sources/vendor-rss.md` once T06 verifies them. | open |
| T05 | Should IOCs taken only from the ThreatFox 1781006 reporter note (`@opengov/form-renderer` 0.2.20, `/tmp/pglog`, `pgmon.service`) be tagged with the CanisterWorm campaign? | No. SPEC does not tie IOC 1781006 to a named campaign (first seen 2026-04-04, after CanisterWorm), so `campaign` is null and the shared canister is the only link. | open |
| T05 | Which reliability weight do sources get when the raw store or the seed first registers them? | A placeholder of 50 (`DEFAULT_RELIABILITY`). T10 (`core/trust.py`) sets the real per-source weights. | open |
| T06 | SPEC D6 allows live recording only against IC hosts, but the npm, PyPI, abuse.ch, GitHub and vendor-RSS collectors need non-IC hosts (listed in each note). | Keep `ALLOWLIST` IC-only. | T06 | The raw gateway turns a GET into an `http_request_update` update call when the canister's `http_request` reply sets `upgrade = opt true` (raw-gateway.md). Our GET could then make the IC run an update call, which strains guardrail 1. | Guardrail wins. T08 first calls `http_request` as an anonymous query through `icp-api.io` and skips the raw GET (recording the reason) if `upgrade` is true. | open |
| T06 | Dashboard API: SPEC names v3, but cursor-paged canister and subnet listings exist only under `/api/v4` (dashboard-api.md). | Use v3 for single-canister and proposal lookups and v4 for the census listings, both on the already allowlisted `ic-api.internetcomputer.org`. | T06 | read_state: the spec marks `/api/v2/.../read_state` as deprecated in favour of `/api/v3`, and `core/ic_client.py` still posts to v2. Manual `cbor2` over `core/http.py`, not icp-py-core, because of the guardrails. BLS certificate verification is pending a library choice, and results are marked unverified until then. | open |
| T06 | How was `tdtqy-oyaaa-aaaae-af2dq-cai` "disabled" in March 2026? A gateway 451 `denylisted` response or a policy-violation body is recorded as a separate takedown signal. SPEC's "governance" wording is left as is. | open |
| T06 | abuse.ch terms give no data licence and require consent for derivative works (threatfox.md, urlhaus.md). | Exports cite only the individual IOCs a case needs, with attribution and a reference link. No bulk redistribution of abuse.ch data. | open |
| T06 | No public source names the PyPI packages hit by CanisterSprawl (pypi.md). | Seed nothing for PyPI. The npm packages and GHSAs in github-advisories.md and vendor-rss.md are the only package IOCs. | open |
| T07 | `make record` needs `ICP_THREAT_INTEL_CONTACT` for the User-Agent (T01 decision), and none is configured. | T07 | Certificates are not BLS-verified (no BLS backend chosen, see T06). | `core/ic_certificate.py` reconstructs the root hash and does spec hash-tree lookup; every read_state event carries `verification: unverified:no_bls`. | T08 | The gateway can turn a raw GET into an update call (`upgrade = opt true`). | T08 | Raw-gateway cassettes cannot be recorded without `ICP_THREAT_INTEL_CONTACT` (same as T07). | `tests/cassettes/raw_gateway_*` are synthetic (`synthetic: true`, placeholder bodies). `tests/collectors/test_raw_gateway_live.py` (marker `live`) re-records them through `make record`. | open |

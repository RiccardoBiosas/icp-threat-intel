# OPEN QUESTIONS

Questions the loop could not ask a human. Each entry records the question, the default the agent chose, and the task id. Review these between runs; to change a decision, edit SPEC.md section 2, and delete BLOCKED.md if the loop stopped on it.

| Task | Question | Default chosen | Status |

| T01 | Guardrail 5 says only "a hash and redacted=true are kept". Redact each matching span or drop the whole body? | Replace each matching span with `[REDACTED:<kind>:<sha256-prefix>]`, keep the rest of the body, set `redacted=true`, keep `sha256` of the original bytes and `stored_sha256` of the stored bytes. Dropping the whole body would destroy H1 evidence whenever a C2 body also contains a token-like string. | open |
| T01 | `raw_snapshots` must be idempotent on identical content. How are repeat observations of an unchanged body recorded? | Unique on `(source_id, url, sha256)`; a repeat returns the existing row and `fetched_at` stays the first fetch. Liveness over time comes from `canister_snapshots` and `events`, which every run writes. No extra table. | open |
| T01 | The census must diff against the previous run, but SPEC's table list has no runs table. | No new table: `canister_snapshots.census_run_id` (UUID) plus one `census.run_completed` event per run with counts, `ceiling_hit` and complete/incomplete subnets. Removals are reported only for subnets complete in both runs. | open |
| T01 | pgvector is in the stack but no table needs a vector column yet. | The initial migration creates the `vector` extension on Postgres only; no vector column until the LLM extension point in `enrichment/` is implemented. | open |
| T01 | For the two-signal rule, does the hand-curated seed file count as its own source type? | No. Each seed IOC carries its original publisher's source type (`threatfox`, `vendor_rss`), so the seed plus the matching ThreatFox collector cannot count as two signals. | open |
